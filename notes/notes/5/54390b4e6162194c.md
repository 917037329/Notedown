三、一个场景说明区别假设主库执行了 5 个事务（GTID 分别为 1-5），从库已同步到第 3 个事务后网络中断。

**传统复制**：从库重连后，会告诉主库：“我上次读到 `mysql-bin.000123` 文件的第 1500 字节”。如果主库的 binlog 已轮转，该位置可能已失效，需要人工介入重新找点。即使能连上，也可能因为重传第 3 个事务而重复执行。

**GTID 复制**：从库只需告诉主库：“我已执行过 GTID 1、2、3”。主库自动计算出应该发送 4、5 给从库。从库收到后检查，发现没执行过，于是执行一次。整个过程自动、精确、不会重复。

GTID (Global Transaction Identifier) 是 MySQL 5.6 引入的一种为每个事务分配全局唯一标识的机制，主要用于简化复制和故障恢复。

## GTID 的结构

text

```
UUID:事务ID
```

*   **UUID**：源服务器的唯一标识（`auto.cnf` 中的 `server_uuid`）
    
*   **事务ID**：该服务器上提交的事务序号，从1开始递增
    

**示例**：`3E11FA47-71CA-11E1-9E33-C80AA9429562:1-100`

## 核心特性

1.  **全局唯一**：整个复制集群中每个事务都有唯一 ID
    
2.  **幂等性**：同一 GTID 的事务只执行一次（自动跳过已执行事务）
    
3.  **无需日志位**：不再依赖 `文件名+偏移量` 定位

## 关键操作

**启用 GTID**（my.cnf）：

ini

```
gtid_mode = ON
enforce_gtid_consistency = ON  # 强制事务安全（不支持 CREATE TABLE...SELECT）
```

**查看 GTID 状态**：

sql

```
SHOW MASTER STATUS;              -- 查看已执行 GTID
SHOW VARIABLES LIKE 'gtid%';     -- 查看 GTID 变量
SELECT @@GLOBAL.gtid_executed;   -- 本实例已执行的所有 GTID
```

**配置 GTID 复制**：

sql

```
-- 从库配置
CHANGE MASTER TO 
    MASTER_HOST='master_host',
    MASTER_USER='repl_user',
    MASTER_PASSWORD='xxx',
    MASTER_AUTO_POSITION=1;      -- 自动使用 GTID 定位
START SLAVE;
```

## 常见场景

**1\. 跳过复制错误**：

sql

```
-- 设置要跳过的 GTID 事务
SET GTID_NEXT='3E11FA47-71CA-11E1-9E33-C80AA9429562:123';
BEGIN; COMMIT;                   -- 注入空事务覆盖
SET GTID_NEXT='AUTOMATIC';
START SLAVE;
```

**2\. 主从切换**：

sql

```
-- 新主库清除自己的执行记录（必须）
RESET MASTER;                    -- 清空旧 GTID 信息

-- 新从库指向新主库（自动同步）
CHANGE MASTER TO MASTER_HOST='new_master', MASTER_AUTO_POSITION=1;
START SLAVE;
```

**3\. 重建从库**：

bash

```
# 从备份恢复后设置已执行的 GTID 范围
SET GLOBAL gtid_purged='3E11FA47-71CA-11E1-9E33-C80AA9429562:1-1000';
```

## 注意事项

*   **不支持事务混合使用**：`CREATE TABLE...SELECT`、临时表 + 事务等不兼容，需改写
    
*   **性能影响**：GTID 持久化有轻微开销（`mysql.gtid_executed` 表）
    
*   **重置需谨慎**：`RESET MASTER` 会清空 GTID 历史，可能导致从库重复执行事务
    
*   **跳过错**：相比传统复制的 `sql_slave_skip_counter`，GTID 跳过错误更麻烦（需注入空事务）
    

## 核心工作原理

主库提交事务时生成 GTID 并写入 binlog；从库的 IO 线程读取后存入 `relay log`，SQL 线程执行前检查 `gtid_executed` 系统变量，若该 GTID 已存在则跳过，保证同一个 GTID 在整个复制拓扑中只执行一次。
